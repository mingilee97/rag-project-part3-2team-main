# 공통 인터페이스와 원본 차이

Baseline은 원래 `07_verify`를 유지하는 사용자 기준 코드이며 최초 실험 `00_baseline`과 구분합니다. Version 1~4는 고정 커밋의 네 원본 흐름입니다. 폴더 번호는 성능 순위가 아닙니다.

공통 코드·설치 의존성은 Baseline에 한 번만 둡니다. 버전별 `version.json`은 parser/chunker/embedder/retriever/generator 역할의 원본 경로, 과거 설정 `historical_settings`, 새 배포 생성기 `deployment_generator`를 구분합니다. 설정 목록 확인은 원래 YAML·노트북의 실행 설정을 자동 변경하지 않습니다.

## Baseline

Baseline 폴더에서 `from team_versions import VersionSession`으로 불러옵니다. `VersionSession('baseline').run(stage, *args, **kwargs)`는 기존 함수의 인자와 반환값을 그대로 전달합니다. parser=load_docs(data_dir), chunker=chunk_fixed(document,size,overlap), embedder=get_embeddings(cfg), retriever=retrieve(cfg,question), generator=pipeline.ask(question,state,cfg)입니다. cfg는 `settings.load('07_verify')`로 읽습니다. 실제 prepare/ingest/index/enrich/ask CLI는 Baseline README에 있습니다.

## 후보 네 흐름

원저작자의 허용 범위를 확인한 뒤 기존 PR #1의 고정 모듈 접수 커밋 `cf4171e577cd481054fdd0aceee79bf87d6f5518`와 같은 로컬 `versions/pipelines` 폴더를 연결합니다. 이 변경에는 그 원본 복사본을 추가하지 않았습니다. `reuse_authorized=True`는 이미 확인한 사용 권한을 호출자가 표시하는 값이며 라이선스를 부여하지 않습니다. 모델·라이브러리·입력 메타데이터는 providers에 연결합니다.

```python
from team_versions import VersionSession

session = VersionSession('v1', bundle_root=local_module_folder,
                         reuse_authorized=True, providers=providers)
session.run('parser')
session.call('stage_cleaning')
session.run('chunker')
session.run('embedder')
session.run('retriever')
session.connect_haiku()     # 개인 ANTHROPIC_API_KEY; 생성 공급자만 변경
session.run('generator')
answer = session.call('answer_question', question, 'basic')
```

Version 1~2: parser → cleaning → chunker → embedder → retriever → Haiku 연결 → generator. Version 3~4: parser → chunker → embedder → Haiku 연결 → generator → retriever. 뒤 두 원본은 generation에서 만든 prompt를 retrieval에서 재사용합니다. connect_haiku 이후 원래 stage_generation_model을 호출하면 원본 모델로 다시 바뀌므로 호출하지 않습니다.

공통 공급자 변경은 반환 규약을 유지하는 LangChain ChatAnthropic을 연결합니다. 기존 원본 검수와 새 생성 모델의 품질 검증을 구분합니다. Version 3의 임베딩은 OpenAI 원본 조건을 그대로 유지하므로 원래 임베딩 실행에는 별도 준비한 벡터 또는 OpenAI 키가 필요할 수 있습니다. Haiku는 임베딩 모델이 아닙니다.

source-lock은 접수 런타임과 단계 코드의 LF 정규화 SHA-256을 확인합니다. 문서·벡터·모델 자산의 재현성까지 보장하지 않습니다. 자동 API 호출·모델 다운로드는 없으며 명시적인 단계 호출에만 실행 비용이 발생할 수 있습니다.
