# 시도한 구성과 최종 선정

2026년 10월 20일 사용자는 제공한 FINAL-02를 최종 실행으로 선택했습니다. 이전 코드가 실행된 조건, 팀원 코드를 접수한 범위, 실제 평가한 범위를 나눠 기록합니다.

## 초기 기준과 팀원 코드 비교

초기 `07_verify`는 KURE-v1·Chroma·dense Top-5·EXAONE을 사용했습니다. 질문 종류 분기, 문서 요약, 숫자·날짜 검증을 포함합니다. 당시의 dev30·holdout10 결과를 이후의 RAGAS 300문항 점수와 같은 척도로 읽지 않습니다.

기존 Version 1·2는 김현경 님 원본의 사업 식별·700/100·BGE·FAISS·BM25·재순위화를 접수했습니다. Version 3·4는 김민협 님 원본의 HWP 보정·parent/child·OpenAI 또는 KoE5 경로를 담았습니다. 소스가 확보되고 모의 실행이 통과한 것만으로 실제 품질 개선이나 최종 채택이 확인되지는 않습니다. 기존 작성자·원본 저장소·고정 SHA는 `history/`와 루트 `SOURCE-NOTES.md`에 남아 있습니다.

## 검색과 생성을 나눠 본 실험

10문서·30문항 실험에서는 임베딩, 답변 프롬프트, Judge, 재순위화 모델, 청크 크기와 사업명 헤더를 바꾸며 비교했습니다. 700/100에서 1000/200으로 바꾼 실험은 한 청크 안에 필요한 근거를 더 담는 방향이었습니다. 검색 순위가 좋아져도 답변 지표의 차이는 작을 수 있어 검색 성과와 답변 성과를 따로 해석했습니다.

이후 100문서·300문항으로 검색 범위를 넓혔습니다. 검색 전용 실험의 Hit@5·MRR은 답변을 실제 생성·채점한 결과가 아닙니다. 여러 절에 흩어진 근거를 함께 확보하는 문제가 남아 parent/child와 질문 분해도 시도했습니다.

## FINAL-01과 FINAL-02

FINAL-01은 parent 1400/200, child 350/50과 질문 분해를 사용했습니다. FINAL-02는 헤더와 질문 분해 없이 일반 1000/200 청크, Dense 20·Kiwi BM25 20, RRF 60, BGE 재순위화 후 상위 6개를 사용합니다. 생성은 같은 Haiku 프롬프트로 기록돼 있습니다.

기록상 FINAL-02의 Judge·F1·Faithfulness가 조금 높지만, 문항별 비교의 신뢰구간이 0을 포함해 차이가 통계적으로 유의하지 않았습니다. 이는 동등성 검정을 통과했다는 뜻은 아닙니다. FINAL-02는 문맥이 약 27% 짧고 검색 중앙값이 약 1.7초로 작아, 추가 질문 분해 호출이 없는 구성을 선택했습니다. 여러 절 질문의 근거 수집 비율은 FINAL-01 0.77, FINAL-02 0.69로 반대 방향인 기록도 남깁니다.

이 정리에서는 기존 저장 결과를 읽고 숫자만 재계산했습니다. 비교의 통계 검정이나 모델 실행을 새로 수행하지 않았습니다. 파싱 캐시가 다른 다섯 문서와 1회 실행이라는 한계도 유지합니다.
