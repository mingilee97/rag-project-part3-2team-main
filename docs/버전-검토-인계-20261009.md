첫 검사는 기존 프로젝트 환경을 쓰며 모델을 호출하지 않는다. 나머지 검사는 Python/Node 표준 라이브러리와 저장된 합성 모듈을 사용한다. CI는 공개 파일의 스키마·해시·금지 자산과 CPU 클라이언트·UI 계약을 검사한다. CI가 실제 모델 품질이나 생성 평가를 실행하지는 않는다.

100문서 검색 비교는 진행 중이며 CPU 생성 pilot12건을 완료했다. 전체504입력 생성은 실측 예상 시간이 생성만 약5.15시간으로 늘어나 첫 입력 전에 안전하게 보류했다. 새로운 결과는 [선정 상태](../versions/selection.json)와 [비교 근거](버전-비교-근거.md)에 반영한다. 실제 실행 PID·진행로그·원문과 응답은 사용자 PC의 로컬 검토 폴더에만 남긴다.

## 재개와 보호 경계

README, AGENTS, 이 문서, `git status -sb`, 최근 커밋을 읽고 이어간다. 재현 자산의 정확한 SHA는 비교 집계와 실행 계획을 확인한다. 이미 실행 중인 로컬 프로세스를 중복 시작하지 않는다. 새 결과는 별도 파일과 체크포인트에 저장하고 기존 봉인 결과를 덮어쓰지 않는다. 실제 원본 자산과 모델 캐시는 별도로 준비해야 한다.

Windows 등록 평가의 GPU 제한 가드를 제거하지 않았다. 공식 CPU 옵션을 명시한 별도 로컬 평가 클라이언트에서 실제 `/api/ps`의 `size_vram=0`을 확인했다. CPU 부품 평가와 기존 등록된 전체 `07_verify` 평가를 구분한다. semantic judge 호출이 없으면 답변 품질 점수는 `null`로 남기며 오류를 0점으로 대체하지 않는다.

## VM 준비와 검색 점수 설명 보완

김현경 문서 어댑터 추가 커밋 `95e75a4c19dba8b30ea7cac7205a1af0c4191287`은 공개되었고 CI가 통과했다. 이후 VM/Colab 요청에 따라 [실행 준비](../evaluation/VM-COLAB.md), 공개 코드15개만 담는 [패키지 허용목록](../evaluation/vm-package.json), 모델 호출 없는 사전 점검과 Linux VM 전용 GPU 실행기를 추가했다. GPU schema는 `vm-gpu-answer-component-v1`이며 pilot12/full504를 별도 출력에 저장한다. 같은 EXAONE digest·Ollama0.35.1을 고정한다. Windows/WSL GPU 실행은 거부하며 기존 CPU 코드와 등록 가드를 보존한다. 비공개 입력·키·모델 전송과 원격 생성 실행은 아직 하지 않았다. 기존 정상 CPU 검색과 생성 보류 상태를 유지한다.

공개 검색 재현 v2는 캐시 revision과 이전 벡터 조건을 로딩 전에 검증한다. 실행 중인 로컬 v1 소스·계획·순위는 그대로 보존한다. 기존14문서의 [BF16 정밀도 진단](../evaluation/aggregates/20261009-bf16-precision14.json)은 원래 dot 순위와 float32 재정규화의 top5 집합 차이를 보여 준다. 엄밀한 코사인이라는 과거 표기를 보완하며 전체100문서 또는 생성 품질의 새 결과로 표시하지 않는다.
